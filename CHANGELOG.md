# Changelog

All notable changes to this project are documented here (Keep a Changelog format).

## [Unreleased]

### Added
- **Autonomous Mode** (`--autonomous`, `config.autonomousMode`): a Manus-inspired workflow — mandatory upfront planning, periodic plan "recitation" back into context on long turns (a plain conversation message, not a system-prompt rewrite, so it works identically across every provider adapter), and an instruction-only system-prompt section asking the model to verify its own work (run tests/lint/the code itself) before declaring a task done. Deliberately adopts Manus's *workflow discipline*, not its *safety posture*: destructive-call auto-approval reuses the exact same `--yolo` bypass path (no second mechanism), and sandboxing (`config.sandboxMode`) plus `allowedWritePaths` are completely untouched by this flag — verified directly that a destructive call in this mode still goes through the same `confirm()` function as any other mode. Building this also surfaced and fixed a pre-existing gap: the one-shot CLI path (`codeagent "<request>"`) had no planning support at all, unlike the REPL and TUI. See `docs/31`.
- Design writeup for **Folder Trust** (`docs/30`) — a first-time-per-folder consent gate modeled on VS Code/Cursor/Windsurf's workspace-trust prompt. Design only in this release; not yet implemented.
- New docs: `docs/30` (Folder Trust, design), `docs/31` (Autonomous Mode).
- **Subagents**: scoped, single-level task delegation via a new `run_subagent` tool — explicit invocation only, no automatic delegation. Definitions live in `.codeagent/agents/<name>.md` (same frontmatter shape as Skills). Reuses `Orchestrator` itself for execution rather than a second engine, so confirm/hooks/permission-rules/Plan Mode all apply identically inside a subagent's own tool calls — verified end-to-end against the real dispatch path, not mocked, including that a subagent's destructive tool calls go through the exact same `confirm()` as the parent and that a subagent starts with a genuinely empty history (no parent-conversation leakage). A subagent's tool registry always excludes `run_subagent` (no recursion, v1 boundary); a definition's `tools:` field can narrow further but never grant beyond what the parent has. New `codeagent subagents` command. See `docs/22`.
- **`run_bash` sandboxing**: previously zero isolation beyond a timeout — under `--yolo` this was full user-level system access. Now confines *writes* to the project root and `allowedWritePaths` via `bubblewrap` (Linux) or `sandbox-exec` (macOS) when available; reads remain unrestricted (deliberately — most legitimate commands need to read system libraries/caches, and the read/write asymmetry matches how `write_file`/`edit_file`'s existing path guard already works). `config.sandboxMode: "auto" | "off"`, default `"auto"`; logs a warning (not silently) when no sandbox is available on the platform. Verified against a real `bwrap` install, not just mocked, including that a timeout correctly tears down the whole sandboxed process tree rather than orphaning it. See `docs/15`.
- **Memory** (`AGENTS.md`, the `CLAUDE.md`-equivalent gap): `AGENTS.md` at the project root (visible, not hidden under `.codeagent/` — same reasoning as README auto-discovery) plus `~/.codeagent/AGENTS.md` for personal cross-project preferences. Both auto-loaded every session, rendered into the system prompt between the admin prompt and the skills index. New `codeagent memory` command. See `docs/23`.
- **Slash Commands**: built-ins `/help`, `/clear`, `/plan` (the last one closing a previously-deferred in-REPL Plan Mode toggle) plus project-scoped custom commands (`.codeagent/commands/<name>.md`, `$ARGUMENTS` substitution — same frontmatter shape as Skills/Subagents). A custom command resolves to a plain prompt string handed to the orchestrator exactly as if typed directly — no new execution concept, no new safety surface. New `codeagent commands` command. See `docs/24`.
- **MCP Client**: connect external tool servers via `.codeagent/mcp.json` (stdio transport, modeled on Claude Code's `.mcp.json`). Uses the official `@modelcontextprotocol/sdk`. Every MCP tool is wrapped into the exact same tool shape built-in tools use — no separate code path for confirm/hooks/permission-rules/Plan Mode. Tools are namespaced `mcp__<server>__<tool>` (collision avoidance and third-party-origin transparency in one mechanism). Defaults to `destructive: true` unless a server's `readOnlyHint` annotation explicitly clears the bar (a server's own `destructiveHint: false` claim alone is not trusted). One server failing to connect doesn't take down the session. Verified against a real subprocess MCP server, not mocked. New `codeagent mcp` command. See `docs/25`.
- **Usage & cost tracking**: `codeagent usage` (`--today`/`--week`/`--all`, default this month) and `codeagent quota`/`codeagent quota set <provider> <limitUSD>`. Global JSONL log under `~/.codeagent/usage/` (same storage convention `SessionStore` uses), advisory-only quotas — nothing blocks a request, a breach only produces a message after the fact. Cost is an explicit estimate reusing `ModelRegistry`'s existing per-model pricing, with `null` (unpriced) kept distinct from `0` (genuinely free, e.g. Ollama). See `docs/26`.
- **Interactive config manager**: `codeagent config --interactive`/`-i` (guided menu, delegates to the existing setup wizard for provider/model), `codeagent config set <key> <value>` (scriptable), `codeagent config validate` (reports which field failed, if any). One shared validation path for both the menu and `set`. Building `validate` surfaced and fixed a real pre-existing crash: a corrupted `~/.codeagentrc` that also happened to look "unconfigured" could crash the CLI with a raw stack trace before any command — including `validate` — got a chance to run; now handled with the same friendly per-field error every other config-loading path already gives. See `docs/27`.
- **TUI theming & vim keybindings**: `config.theme` (`default`/`monochrome`/`high-contrast`, one shared semantic palette the status header and session log read from) and `config.vimKeybindings` (an opt-in, genuine subset of vim — not full emulation — for the TUI's input box: `i`/`a`/`I`/`A`/`h`/`l`/`0`/`$`/`x`/`dd`; Enter always submits regardless of mode). Both purely additive — defaults preserve the exact original TUI experience for anyone not opting in. See `docs/28`.
- **Agent SDK**: `import { Orchestrator, ToolRegistry, createDefaultRegistry, ... } from "codeagent/sdk"` — a curated, individually-audited export surface for embedding codeagent as a library, not a blanket re-export of internals. `package.json`'s `exports` field defines only the `./sdk` subpath; a bare `import "codeagent"` is a hard, unambiguous error. New `SDK_VERSION` stability contract, independent of the package's own version. Verified with a real `npm pack` → install → import round trip into a throwaway consumer project (not just relative-path imports), including a full `Orchestrator.runTurn()` executed entirely through the packaged SDK. See `docs/29`.
- **Two-tier skills index**: the skills system prompt section previously cost ~6,500 tokens/turn at 102 skills regardless of relevance — flagged as a known tradeoff before scaling up, now fixed. `config.skillsIndexMode: "compact" | "full"`, default `"compact"`: the system prompt carries only skill *names*, and a new `skill_info` tool fetches a specific skill's description on demand. Measured ~5,500 tokens/turn saved at the 102-skill scale. See `docs/19`.
- New docs: `docs/22` (Subagents), `docs/23` (Memory), `docs/24` (Slash Commands), `docs/25` (MCP Client), `docs/26` (Usage Tracking), `docs/27` (Interactive Config Manager), `docs/28` (TUI Polish), `docs/29` (Agent SDK).

### Fixed
- **Windows/macOS keychain read-path**: `_getKeyWindows` and `_getKeyMacOS` used to catch a failed platform credential-store command and return `null` directly, silently skipping the local-storage fallback every *save* path (and Linux's own get path) already correctly falls through to. Concretely, on Windows: `Get-StoredCredential` commonly fails simply because the CredentialManager PowerShell module isn't installed — an ordinary environment, not an edge case — meaning a key that had fallen back to local storage at save time could never be read back at all. Found via an independent Windows-environment audit; the equivalent macOS defect was found while fixing the reported one, not itself reported. Both now fall through to local storage on any platform-command failure, matching `_getKeyLinux`'s existing correct pattern. Regression-tested for both platforms.
- `docs/00-index.md` (the documentation index) hadn't been updated since doc 21 — docs 22 through 29 above existed but weren't listed anywhere a reader would find them. Also removed `docs/05-tools-and-skills.md`, an orphaned duplicate left behind by that file's 2026-07-14 rename to `docs/05-tools.md` that never got cleaned up — nothing referenced it, but it sat alongside the real file as a stale trap for the next reader.
- `run()`'s first-run-setup detection could crash uncaught (raw stack trace) on a corrupted `~/.codeagentrc` that also happened to look "unconfigured" (missing/invalid `providers` key) — found while building `codeagent config validate`, whose entire purpose is handling exactly this. Now caught and reported with the same friendly, field-specific message every other config-loading path already gives.
- The plain REPL (the documented non-TTY/piped-input/CI fallback, `docs/21`) silently lost input in two distinct ways, found during a fresh-eyes audit of the whole CLI: (1) its `readline.Interface` was created at the top of `startRepl`, before several `await`s (MCP connection, project context, memory loading) that take real time — piped input arriving during that window could be consumed and lost before any `question()` call was pending to receive it; (2) even after fixing that, `readline/promises`' `question()`-in-a-loop pattern has a separate, genuine limitation with fully-buffered, immediately-closing piped input — only the first line ever gets delivered through nested `question()` calls, and a second call made after the stream has already ended never resolves or rejects at all (verified directly against a minimal reproduction). Neither issue affects real interactive typing at a terminal (a human can't type faster than setup completes, and a live TTY session never closes stdin mid-conversation) — both specifically affect scripted/automated usage, which the plain REPL is explicitly documented to support. Fixed by moving interface creation to immediately before the loop and switching the loop itself to `for await (const line of rl)`, Node's documented async-iterator pattern for readline, which correctly delivers every already-buffered line regardless of timing.

- Rich interactive session: a real terminal now gets an Ink-based TUI automatically — a live status header (model, provider, plan mode, skills count, rules count) and **Tab** to open a mid-session model switcher, filterable and keyboard-navigable, built from your actually-configured providers. History carries over across a switch, same guarantee `codeagent use` already had, now reachable without leaving the session. Falls back automatically to the existing plain REPL for piped input, CI, or any non-TTY context — or on demand via `CODEAGENT_PLAIN_REPL=1`. New `Orchestrator.setProvider()` API underneath it. See `docs/21`.
- Permission rules & Plan Mode: `.codeagent/permissions.json` defines fine-grained allow/deny rules per tool+pattern (e.g. always allow `npm test*`, always deny writes to `*.env`), checked before the existing confirm/`--yolo` gate — deny always wins when both an allow and a deny rule match. `--plan` makes destructive tools describe what they would do instead of doing it, for the whole session — verified against real tools and real files, not just mocks. New `codeagent permissions` command lists configured rules. See `docs/20`.
- Skills: discoverable `SKILL.md` capabilities under `.codeagent/skills/<name>/SKILL.md`, with progressive disclosure — the system prompt gets a one-line index (name + description) for each skill, never full content; the model reads a specific skill's full instructions on demand via the existing `read_file` tool, only when it decides that skill applies. New `codeagent skills` command lists what's discovered. **102 skills ship with the project** — languages, testing, git workflow, code quality, APIs, databases, security, DevOps, frontend, docs, performance, debugging, concurrency, data handling, architecture, cloud, mobile, tooling, and communication — added in 20 reviewed batches of 5, each verified for clean discovery (0 warnings, 0 duplicate names) before continuing. Real, measured cost at that scale: the index alone is ~6,500 tokens on every turn regardless of relevance, flagged before scaling up, not discovered after. `allowed-tools` frontmatter is parsed but still not enforced — permission rules (below) landed, but nothing yet wires them specifically to a skill's `allowed-tools` list. See `docs/19`.
- Hooks: `PreToolUse` and `PostToolUse` lifecycle events, configured via `.codeagent/hooks.json` — a `PreToolUse` hook can block a tool call before it runs (e.g. reject a dangerous shell command), and a `PostToolUse` hook can attach context to the result the model sees (e.g. "formatted with prettier"). `SessionStart`/`SessionEnd` events also fire around the session lifecycle. New `codeagent hooks` command lists what's configured. See `docs/17`.
- Multi-provider management: `codeagent providers` lists every configured provider, which is active, and its key source; `codeagent use <provider> [model]` switches the active provider/model persistently. Session history carries over across a provider switch unchanged.
- First-run setup: running `codeagent` on a machine with no provider configured now walks through setup automatically before your command runs, instead of failing with a missing-env-var error.
- `codeagent setup`, run again after the first time, now offers to add another provider, switch the active one, or reconfigure a key, instead of repeating the fresh-install flow.
- Admin system prompt: `codeagent system-prompt set "<text>"` / `show` / `clear` — a standing instruction that applies across every project on the machine, layered with priority above project-specific context.
- CI: GitHub Actions now lints and runs the full test suite on every push/PR (Node 22.x and 24.x), and a tag-triggered workflow publishes to npm after re-verifying lint/tests and that the tag matches `package.json`'s version.
- New docs: `docs/16` (Claude Code feature-parity audit, driving the project's forward roadmap), `docs/17` (Hooks), `docs/18` (provider management & admin system prompt).

### Fixed
- `package.json`'s `engines.node` — was stale at `>=18.0.0` (Node 18 and 20 are both past upstream end-of-life as of mid-2026); now `>=22.0.0`, matching what Ink (the new TUI dependency) genuinely requires, not just CI's target matrix.
- `.gitignore` blanket-ignored the entire project-level `.codeagent/` directory, silently making `hooks.json` (since Phase 3) and now `skills/` un-shareable via git despite both being explicitly designed to be committed and shared with a team. Real local state (session/undo history) lives in `~/.codeagent/sessions` — the user's home directory, never inside a project's repo — so nothing under a project's `.codeagent/` actually needed excluding.
- `test/e2e/agent-coding.test.js` — rewritten as a genuine end-to-end test. It previously imported a nonexistent default export, mocked the tool registry with a shape that didn't match the real class, and used `require()` inside an ESM module; it had never actually run. Now runs the real `Orchestrator` against the real `ToolRegistry` and real tools (actual file I/O in a temp directory), faking only the LLM response — confirmed via real CI, not just locally.
- `actions/checkout@v4` / `actions/setup-node@v4` bumped to `@v5` in both workflows — v4 still targets the Node 20 runtime GitHub is removing from Actions runners in September 2026; v5 runs natively on Node 24.
- `codeagent setup` used to discard every choice you made the moment the process exited — nothing was ever written to disk. It now persists to `~/.codeagentrc` as each step completes.
- An API key saved to the OS keychain during setup was never actually read back at runtime (`useKeychain: true` had no effect). Every provider now resolves its key from the environment variable first, falling back to the keychain.
- A crash in `codeagent setup`'s hidden API-key input: typing any character would throw `char.charCodeAt is not a function`, because keystrokes arrived as raw `Buffer`s rather than strings. Hidden input now also handles pasted (multi-character) input and falls back to a visible prompt on a non-TTY stdin instead of crashing.
- A shell-injection risk in keychain storage: API keys were previously interpolated into `security`/`pass`/`cmdkey` command strings. Keys are now passed via argument arrays or piped through stdin — never built into a shell command string.
- The stray `<![CDATA[ ... ]]>` wrapper around the entire README that would have rendered broken on GitHub/npm.

### Known issues
- `npm audit` reports vulnerabilities in `esbuild`/`vite`, transitive dependencies of `vitest@^2.0.0` — confirmed pre-existing (that version was already declared before this release's work began, via `git show HEAD:package.json`), not introduced by the new `ink`/`react` dependencies. Dev-only; esbuild's local dev server is never part of the published package. A fix means a `vitest` v2→v4 major bump with real breaking-change risk to the full test suite — a deliberate, separate follow-up, not bundled into this release.

## [0.1.0] - 2026-07-11

### Added
- Initial implementation of the full architecture described in `docs/`: CLI/REPL, Agent Core loop, Provider Layer (Anthropic + OpenRouter adapters), 6 core tools (`read_file`, `write_file`, `edit_file`, `list_dir`, `search_code`, `run_bash`), Safety Layer with `--yolo` bypass and audit logging, Session Store with resumable sessions and undo, layered Configuration system.
- OpenRouter adapter providing a path to free-tier models, alongside Anthropic as the default provider.
- Test suite (vitest) covering tools, config layering, safety confirmation gate, and the orchestrator loop against a fake provider.
